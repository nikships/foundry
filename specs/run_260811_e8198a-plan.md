# MCP Support Implementation Plan

## 1. Types (`apps/desktop/src/shared/types.ts`)
- Export a new `UserMcpServer` interface/type. It must support the three transports SDK 0.7.0 accepts:
  - `stdio`: `{ type: 'stdio', command: string, args?: string[], env?: Record<string, string> }`
  - `http`/`sse`: `{ type: 'http' | 'sse', url: string }`
  - Shared fields: `id: string`, `name: string`, `disabled: boolean`.
- Extend `AppSettings` to include `mcpServers: UserMcpServer[]`.

## 2. Settings Store (`apps/desktop/src/main/store/settings.ts`)
- Add Zod schemas for the MCP server types.
- Add `mcpServers: z.array(mcpServerSchema)` to `appSettingsSchema`.
- In `defaultSettings()`, add `mcpServers: []`.
- In `migrate(raw)`, safely preserve existing `mcpServers` (defaulting to `[]` if missing).

## 3. Settings UI (`apps/desktop/src/renderer/screens/SettingsScreen.tsx`)
- Add a new pane to `PANES` (e.g., `{ id: 'mcp', label: 'MCP Servers' }`).
- Build UI to list, create, edit, enable/disable, and remove MCP servers.
- Use `patchSettings({ mcpServers: nextMcpServers })` to persist changes.
- Ensure Zod validation failures surface via the existing error banner or field hints without crashing the app.

## 4. Droid SDK Transports
- **`apps/desktop/src/main/droid/sdk/transport.ts`**: Add `userMcpServers?: UserMcpServer[]` to `TransportSessionOptions`.
- **`apps/desktop/src/main/droid/sdk/daemon-session.ts`**: 
  - Expand the local `DaemonMcpServerConfig` type to allow `stdio` (command, args, env) and `sse` (url) forms (it currently only allows `http` for the loopback).
  - In `start()`, map the enabled servers from `this.opts.userMcpServers` to the wire config shape and append them to the `mcpServers` array before calling `sessions.create` or `sessions.resume`.
- **`apps/desktop/src/main/droid/sdk/session.ts`**:
  - In `start()`, map enabled servers from `this.opts.userMcpServers` to the standard SDK `mcpServers` configuration format.
  - Append them alongside the array containing `createFoundryMcpServer(...)` before calling `createSession` or `resumeSession`.

## 5. Executor Wiring
- **`apps/desktop/src/main/engine/executor.ts`**: Add `mcpServers: UserMcpServer[]` to `ExecutorDeps`. When calling `new AgentSession(...)`, inject `userMcpServers: this.deps.mcpServers.filter(s => !s.disabled)`.
- **`apps/desktop/src/main/engine/registry.ts`** (or wherever `ExecutorDeps` is constructed): Pass `mcpServers: appStore.settings.get().mcpServers` into the `Executor` constructor deps.
- **`apps/desktop/src/main/droid/agent.ts`**: Add `userMcpServers?: UserMcpServer[]` to `AgentSessionDeps` and pass it through `transportOpts()` into `TransportSessionOptions`.

## 6. Roster Tool Policy
- The allowlist logic inside `applyToolPolicy` (in `session.ts` and `daemon-session.ts`) dynamically complements against `listTools()`. Since `FOUNDRY_TOOL_IDS` are hardcoded as protected, user MCP tools will behave perfectly: they are enabled by default but correctly disabled if a restrictive allowlist is present and omits them. No changes are required here beyond ensuring they successfully register on the session.

## Verification
- Start Foundry and verify the "MCP Servers" settings pane functions correctly.
- Add an MCP server, start a run, and verify the initialized `SdkSession`/`DaemonSession` payloads contain the configured server.
- Run `npm run check` from `apps/desktop` and ensure typechecks, linters, and unit tests all pass.
