# Plan: Glanceable live Activity marks in the sidebar

## Goal

Running rows in the Factory desktop sidebar Activity list must read as still working at a glance. Finished rows stay static. The live treatment is a dedicated local animation on the Activity mark (persistent core plus a ping/ring), not the global opacity `pulse`. `prefers-reduced-motion: reduce` stops the loop and still leaves a static live-vs-finished distinction.

## Non-goals

- Do not change `@keyframes pulse` in `apps/desktop/src/renderer/design/tokens-base.css` (opacity 1 → 0.35 → 1). StatusBadge, Waterfall, Inspector, Smith transcript, DetectionPanel, SaveState, PhaseDrawer, and inspector entries keep using it.
- Do not change any other surface that uses `animation: pulse`.
- Do not change Activity filtering (`selectActivityRuns` / `useActivityRuns(projectId)`), row click → `onOpenInspector`, `statusColor` / `statusWord`, `data-testid={`sidebar-run-${run.runId}`}`, or collapsed-rail hiding of the list.
- Do not add Playwright e2e as a gate. Do not change website, main-process, IPC, stores, or view-models.
- Do not animate the row, the request text, or the meta line. Only the live mark.
- Do not use bouncy/spring motion. Factory motion is quick and mechanical (`--ease: cubic-bezier(0.4, 0, 0.2, 1)` in `tokens-base.css`; press scale in `factory.css`).

## Current behaviour (grounding)

`apps/desktop/src/renderer/components/layout/Sidebar.tsx` (Activity section, ~248–285):

- Row is live iff `run.status === 'running'`.
- That toggles `styles.runDotLive` on a 6px span whose `background` is `statusColor(run.status)`.
- Finished `RunStatus` values are `accepted`, `rejected`, `failed`, `killed` (`apps/desktop/src/shared/types.ts`).
- Click calls `onOpenInspector?.(run.runId)`. List is omitted when `collapsed` or empty.

`apps/desktop/src/renderer/components/layout/Sidebar.module.css`:

```css
.run-dot {
  flex: none;
  width: 6px;
  height: 6px;
  border-radius: 50%;
}
```

That fade is too subtle, and it ignores `prefers-reduced-motion`: duration is hardcoded `2s`, while reduced-motion only zeroes `--fast` / `--normal` / `--slow` in `tokens-base.css`. Under reduced motion a live row is the same 6px dot as a finished one.

CSS modules use `localsConvention: 'camelCase'` (`electron.vite.config.ts`), so `.run-dot-live` is already `styles.runDotLive`. Keep that class name.

Renderer tests are `environment: 'node'` source/unit tests (`vitest.config.ts`). There is no testing-library. Pin this change with `readFileSync` assertions on TSX + CSS, same style as `apps/desktop/tests/renderer/design-navigation.test.ts`.

## 2. CSS: persistent core + local ping, static halo, reduced-motion

### `apps/desktop/src/renderer/components/layout/Sidebar.module.css`

Replace `.run-dot` / `.run-dot-live` (today ~257–265) with the block below. Do not keep `animation: pulse` anywhere in this file.

```css
.run-dot {
  flex: none;
  position: relative;
  isolation: isolate;
  width: 6px;
  height: 6px;
  border-radius: 50%;
}

/* Live vs finished: a 1px halo that never animates and never dims the core. */
.run-dot-live {
  box-shadow: 0 0 0 1px currentColor;
}

/* Ping sits behind the core (z-index: -1 + isolation) so the 6px fill
   stays at full opacity on every frame. */
.run-dot-live::after {
  content: '';
  position: absolute;
  inset: 0;
  border-radius: inherit;
  background: inherit;
  z-index: -1;
  pointer-events: none;
  animation: run-dot-ping 1.1s var(--ease) infinite;
}

@keyframes run-dot-ping {
  0% {
    transform: scale(1);
    opacity: 0.5;
  }
  100% {
    transform: scale(2.5);
    opacity: 0;
  }
}

@media (prefers-reduced-motion: reduce) {
  .run-dot-live::after {
    animation: none;
    content: none;
  }
}
```

Why this shape:

- Core is the existing 6px filled disc. It has no `opacity` or `transform` animation, so it cannot fade away.
- Halo (`box-shadow: 0 0 0 1px currentColor`) is the static live affordance. Finished rows have no halo. This is what reduced-motion users still see.
- Ping is a local `@keyframes run-dot-ping` in this module (Vite will hash the name). It is not the global `pulse`. Scale + fade on the `::after` copy, never on the core.
- `1.1s` + `var(--ease)` is quicker than the current 2s fade and uses the factory curve. No bounce, no spring, no `cubic-bezier` overshoot.
- Reduced-motion must be an explicit `@media (prefers-reduced-motion: reduce)` that sets `animation: none` (and drops the ping). Do not rely on `--fast/--normal/--slow` — those tokens are not used for this loop, and zeroing them would not add a halo.
- `background: inherit` copies the inline status colour onto the ping, so running stays `--status-running` (accent) without a second inline style.

Do not:

- Put `@keyframes run-dot-ping` in `tokens-base.css`.
- Name the local keyframes `pulse`.
- Animate `.run-item`, `.run-name`, or `.run-meta`.
- Grow `.run-dot` itself (layout stays 6px; `::after` is absolutely positioned).
- Use `will-change`.
- Use `var(--fast)` / `var(--slow)` as the loop duration.

The ping can clip slightly at the first/last row because `.runs-list` is `overflow-y: auto`. Scale 2.5 on a 6px disc is ~15px; that is acceptable. Do not raise list overflow to `visible`.

## Pitfalls

- **Do not edit `tokens-base.css` `@keyframes pulse`.** Other live chips would change with it.
- **CSS-module keyframes stay in `Sidebar.module.css`.** Vite hashes a local `@keyframes run-dot-ping` together with `animation: run-dot-ping`. Do not `:global` it. Do not reuse the name `pulse`.
- **`prefers-reduced-motion` already zeroes `--fast/--normal/--slow` only.** A hardcoded duration would keep looping. The new media query is required. Do not use those tokens as the ping duration.
- **`z-index: -1` on `::after` needs `isolation: isolate` on `.run-dot`**, or the ping paints behind the row.
- **`currentColor` needs `color: statusColor(run.status)`** on the span; `background` alone will not tint `box-shadow` / a border.
- **Do not pass `running` via `endedAt === null`.** Status is the contract; a stuck row with `status !== 'running'` must stay static.
- **Do not restyle collapsed rail.** Activity is already omitted when `collapsed`.
- **File size / CSS collision scripts do not care about this change.** No new `<style>` block, no 10 MiB asset.
