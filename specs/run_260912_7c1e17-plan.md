# Plan — Smith voice full-screen on the Smith screen (run_260912_7c1e17)

## 1. Goal

When the operator is on the full-page Smith chat screen (`view === 'smith'`) and
activates the mic/voice launcher, Smith voice renders as a **full-screen
experience** instead of the current small anchored panel, so voice matches
Smith's full-screen state. On every other screen the existing small popover
behavior is unchanged.

Full-screen voice must keep 100% of today's voice behaviors: idle / connecting /
live / error states, start, mute/unmute, end/cancel, close-with-focus-return,
Escape-to-close, live session surviving navigation, proposal notice opening
Smith chat, settings link opening settings.

Constraints handled explicitly:

- Closing the UI keeps live audio connected wherever it does today (close ≠ stop).
- Dialog semantics + focus management preserved in both variants.
- Layout works for short viewports (scroll, no clipping, no overlap with titlebar).

## 3. Design

Add a `variant: 'popover' | 'fullscreen'` prop to `SmithVoiceOverlay`,
computed in `App.tsx` as `view === 'smith' ? 'fullscreen' : 'popover'`.
`popover` renders exactly today's markup/CSS. `fullscreen` renders the **same
panel content** (same component, same testids, same handlers) inside a
full-screen backdrop instead of the anchored `.panel`.

No session/hook changes. No new IPC. No `SmithScreen.tsx` changes (the overlay
stays owned by `App.tsx` so it survives navigation).

### Why this shape

- Sharing one content component guarantees "keep today's voice behaviors" —
  there is only one copy of the state machine wiring (start/stop/mute/close,
  proposal notice, settings link, footer copy).
- Deriving the variant from `view` in `App.tsx` (not from inside the overlay,
  not from the URL) keeps the session component mounted across navigation, so
  `open` + live audio survive a popover↔fullscreen flip exactly as live audio
  survives navigation today.
- A CSS-only backdrop + larger card (not a new route/modal library) preserves
  `role="dialog"` semantics, existing testids, and the z-index story
  (voice z-70, below modals 90+ per `SmithBubble.module.css` comment).

## 6. Edge cases

1. **Live session + navigation while open**: `open` and refs persist (single
   mount, no key, no reset on `variant` change). Navigating Smith→Runs flips
   fullscreen→popover with status/mute/transcript intact; Runs→Smith flips back.
2. **Proposal notice while already on Smith**: `onOpenSmith()` no-ops; close
   still reveals the chat. No double-navigation.
3. **Connecting → navigate**: pending token/mic/socket refs are variant-agnostic;
   `ready()` still fires; status still flips to live in whichever variant is
   showing. Cancel (`stop` while connecting) still tears down (existing
   "cancelling a pending token" test must pass).
4. **Scope switch mid-session**: `useSmithVoice` teardown on `scopeId` change —
   unchanged.
5. **Short viewport / small window**: `.fullscreen` scrolls (`overflow-y: auto`),
   orb + caption shrink under 700px height, actions wrap. Panel never underlaps
   the titlebar (`inset` starts at `--titlebar-h`).
6. **Reduced motion**: orb already respects `prefers-reduced-motion`; backdrop
   animation uses the existing `--fast` token — acceptable, no new motion.
7. **Launcher overlap on Smith screen**: `.anchor` position is unchanged
   (top-right titlebar band); the fullscreen backdrop starts below the titlebar
   so the launcher stays clickable to toggle.

## 9. Risks

- `position: fixed` inside `.anchor`: safe only because `.anchor` has no
  `transform/filter/perspective` (which would make it the containing block).
  Builder must not add a transform to `.anchor`.
- Duplicate `id="smith-voice-panel"`: only one variant renders at a time —
  guaranteed by the single `open &&` branch on `variant`. Never render both.
- Token check: verify `--s8`/`--s6`/`--text-2xl` exist in
  `apps/desktop/src/renderer/design/tokens-base.css` before using; fall back to
  confirmed tokens.
