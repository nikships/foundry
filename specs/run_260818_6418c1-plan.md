# Plan: Remove truncation from Dropdown options — show full titles and descriptions

## Problem

The pipeline-selector `<Dropdown>` in `RunsScreen` (and everywhere else the component is used with descriptions) truncates both the **label** (single-line `text-overflow: ellipsis`) and the **description** (`-webkit-line-clamp: 2`). When choosing a pipeline, the user can't read the full name or purpose, making it hard to make an informed decision.

The screenshot shows:

- "Plan → Build → Test …" (title truncated with ellipsis)
- "The standard chain: spec first, implement it, prove it…" (description truncated at 2 lines)
- Similar truncation on "Full SDLC → PR" and "Diagnose → Fix → PR" items

## Root causes (all in one file)

**File:** `src/renderer/components/ui/Dropdown.module.css`

1. **`.label`** — has `overflow: hidden; text-overflow: ellipsis; white-space: nowrap;` → truncates the title to one line.
2. **`.description`** — has `display: -webkit-box; -webkit-line-clamp: 2; -webkit-box-orient: vertical; overflow: hidden;` → clamps description to 2 lines.
3. **`.menu`** — the `measure()` function in `Dropdown.tsx` caps `maxHeight` to `Math.min(320, ...)` → a 320px ceiling may not fit all options with full text.

## Changes

### 1. `src/renderer/components/ui/Dropdown.module.css`

#### a) `.label` — allow wrapping

Remove the three truncation properties and let the label wrap naturally.

**Replace:**

```css
.label {
  min-width: 0;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
  font-size: var(--text-sm);
  color: var(--text);
}
```

**With:**

```css
.label {
  min-width: 0;
  font-size: var(--text-sm);
  color: var(--text);
  font-weight: 500;
}
```

`font-weight: 500` keeps labels visually distinct from descriptions now that they can span multiple lines.

#### b) `.description` — remove line-clamp, show full text

Remove the line-clamp and overflow-hidden rules so the full description is visible.

**Replace:**

```css
.description {
  font-size: 11px;
  line-height: 1.35;
  color: var(--text-faint);
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```

**With:**

```css
.description {
  font-size: 11px;
  line-height: 1.35;
  color: var(--text-faint);
}
```

### 2. `src/renderer/components/ui/Dropdown.tsx`

#### a) Increase the `maxHeight` ceiling from 320 → 480

In the `measure()` callback, change the cap so the menu can grow taller to accommodate full-text items. The menu is already scrollable, so this is safe — it just lets more content be visible at once.

**Replace:**

```ts
const maxHeight = Math.max(
  140,
  Math.min(320, openUp ? spaceAbove - MENU_GAP : spaceBelow - MENU_GAP),
);
```

**With:**

```ts
const maxHeight = Math.max(
  140,
  Math.min(480, openUp ? spaceAbove - MENU_GAP : spaceBelow - MENU_GAP),
);
```

#### b) Increase the `MIN_MENU_WIDTH` from 180 → 320

With full text now visible, wider menus render better. This ensures the dropdown menu is at least 320px wide so that titles and descriptions have breathing room and don't force excessive vertical growth.

**Replace:**

```ts
const MIN_MENU_WIDTH = 180;
```

**With:**

```ts
const MIN_MENU_WIDTH = 320;
```

### Summary of files changed

| File                                             | What changes                                                                              |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| `src/renderer/components/ui/Dropdown.module.css` | `.label`: remove `overflow/ellipsis/nowrap`; `.description`: remove `line-clamp/overflow` |
| `src/renderer/components/ui/Dropdown.tsx`        | Raise `MIN_MENU_WIDTH` 180→320, `maxHeight` cap 320→480                                   |

No other files need to change — the Dropdown is a generic component and these CSS changes propagate everywhere it is used.

## Verification

1. **`npm run check`** — full gate (typecheck, lint, format, knip, tests, build, CSS collision check). No functional logic changes, so existing tests should pass unchanged.
2. **Visual verification** — After building (`npm run dev`), open the RunsScreen and click the pipeline dropdown. Confirm:
   - Pipeline titles like "Plan → Build → Test → PR" are fully visible (no "…").
   - Descriptions like "The standard chain: spec first, implement it, prove it with the project's own tests, then send a PR" show in full.
   - The menu scrolls if it exceeds viewport space.
   - The menu is wider, giving text more horizontal room.
3. **Other Dropdown usages** — Spot-check dropdowns in Settings, Roster, Inspector, and Onboarding screens to confirm they also benefit and nothing breaks.

## Risks

- **Wider minimum width** could overflow very narrow viewports. The existing `Math.min(..., viewportW - VIEWPORT_PAD * 2)` in `measure()` already clamps to viewport width, so this is safe.
- **Taller items** mean fewer visible at once if there are many. The menu scrolls, and the higher max-height (480px) mitigates this. The prior 320px cap was quite conservative.
- Other consumers of `<Dropdown>` that have short labels/descriptions will look the same — the only change is that long text is no longer cut off.
